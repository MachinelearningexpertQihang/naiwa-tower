# 奶蛙之塔 · 代码导读

这份文档写给以后要改这个游戏的人（包括以后的自己）。读完应该能回答三个问题：

1. 一个文件管什么，想改某样东西该去哪找；
2. 从点「开始冒险」到打完一场战斗，代码按什么顺序跑；
3. 想加一张牌、一个遗物、一个敌人、一个事件，具体要写哪几行，哪些坑会踩。

文档对应的是 **5.6** 版本。代码一直在长，行号会变，所以下面一般只写「在哪个文件、叫什么函数」，用搜索去找。

## 一、仓库里有什么

GitHub 仓库的根目录就是**打包好、能直接玩的游戏**（和上传到 B站 Toy 的内容一样，只是少了 B站 的 SDK 那一行）。

| 位置 | 是什么 |
|---|---|
| 根目录 `index.html`、`*.js`、`*.css`、`bg/` | 构建后的游戏。直接用浏览器打开 `index.html` 就能玩 |
| `_src/` | 源码。改游戏改的是这里，然后重新构建 |
| `_story/` | 写剧情时用过的脚本 |
| `tools/` | 平衡用的表格和脚本（卡牌预算、重新平衡记录） |
| `tools/tests/` | 自动测试，见下一节 |
| `download/` | 每个版本上传给 B站 的 zip |
| `docs/` | 文档（就是这份） |

`_src/` 里每个文件管什么：

| 文件 | 大小（约） | 管什么 |
|---|---|---|
| `index.html` | 3 KB | 页面骨架：一个 1280×720 的 `#stage`，里面是各个界面（`#title`、`#map`、`#battle`、`#event`……）和固定的层（`#fx` 特效、`#talk` 对话、`#ov` 弹窗）。按顺序引入下面这些脚本 |
| `music.js` | 32 KB | 配乐。不是音频文件，是**用代码写的乐谱**（和弦、旋律），浏览器实时合成。`TR` 是所有曲子，`playMusic(名字)` 切歌 |
| `sx.js` | 395 KB | 音效采样（打击声、金币声……），base64 编码 |
| `voice.js` | 49 KB | 角色的叫声采样 |
| `sfx.js` | 17 KB | 音效引擎：`sfx(名字)` 放一个合成的音效，`sxPlay(采样名, 音量, 音高)` 放一个采样 |
| `ui.js` | 147 KB | 矢量图标 `ICON`、天气图标 `WXICON`、各种 SVG 场景（主页背景、事件背景） |
| `data.js` | 247 KB | **游戏数据**：卡牌 `CARDS`、敌人 `ENEMY`、遗物 `RELICS`、药水 `POTIONS`、状态 `STAT`、剧情 `STORY`、成就 `ACH`、小院成长 `META`、敌人组合 `ENCS`、楼层 `ACTS` |
| `lines.js` | 41 KB | 台词：敌人喊话 `ELINE`、主角台词、酒馆老板 `TAVERN` |
| `story40.js` | 30 KB | 4.0 加的剧情（结局、梦境） |
| `toy.js` | 16 KB | 和 B站 Toy 平台打交道：云存档 `CLOUD`、本机备份 `NWB`、排行榜 `LB` |
| `game.js` | 512 KB | **主程序**：界面、地图、战斗、奖励、商店、事件……几乎所有逻辑 |
| `ss55.js` | 124 KB | 5.5、5.6 加的东西：两条 SS 线、秘密房间、新塔况、新遗物、自动省电、屏幕适配的背景……全部用「包一层」的方式挂在 game.js 上（见第九节） |
| `style.css` | 331 KB | 所有样式。末尾 `/* ==LITE-AUTO== */` 后面那段是脚本自动生成的，**不要手改** |
| `img0.js`…`img3.js` | 各 <1 MB | 所有角色、卡面图片，base64 编码。**构建时自动生成** |
| `font*.css` | — | 字体子集，**构建时自动生成** |
| `bg/*.jpg` | — | 战斗和地图的背景照片 |

> 为什么图片要编码成 js？B站 Toy 要求每个文件不超过 1 MB，而且是离线包。把图片切成几个 js 文件，既不超限，又不用发几百个小文件。

## 二、怎么构建、怎么测

### 构建

源码在开发机的 `naiwa-tower/src/`（就是仓库里的 `_src/`）。构建命令在 `naiwa-tower/` 下：

```bash
python3 mklite.py      # 改过 style.css 就要先跑这个：重新生成「省电模式」那段 CSS
python3 build.py       # 打包到 dist/：编码图片、切字体子集、复制文件、给文件名加版本号
python3 build.py --nofont   # 不重新切字体，快很多（只改了逻辑时用）
```

`build.py` 做的事：

1. 把 `data.js`、`game.js`、`ss55.js` 等所有文件的文字拼起来，扫出用到的**图片名**（比如 `"e_v_champ"`、`"v_horn"`），只把用到的图片打包进 `img*.js`。图片源文件在 `sr/out/*.png`，`e_` 开头的名字会自动做成敌人用的版本（加描边）。
2. 检查所有剧情对话里用到的头像是不是都有图，缺了会打印 `!!! 对话头像缺图`。
3. 扫出用到的**所有汉字**，从字体里切出子集写进 `font*.css`。所以加了新的字，必须重新构建（不加 `--nofont`），否则新字会显示成系统字体。
4. 把 `index.html` 里的 `xxx.js` 改成 `xxx.js?v=5.6`，防止玩家浏览器用旧缓存。版本号来自 `game.js` 第 3 行的 `const VER="5.6"`。

### 打包给 B站

```bash
cp -r dist toy56
# 在 <meta charset="utf-8"> 后面插入 B站 的 SDK
sed -i '0,/<meta charset="utf-8">/s//<meta charset="utf-8"><script src="\/\/s1.hdslb.com\/bfs\/seed\/toy\/app\/sdk\/toy-sdk.js"><\/script>/' toy56/index.html
find toy56 -size +1000k     # 必须什么都不输出：每个文件都要小于 1 MB
cd toy56 && zip -qr ../naiwa-tower-bilibili-toy-v5.6.zip .
```

### 自动测试

在 `tools/tests/`。用的是 Playwright（无头 Chrome），真的打开游戏、点按钮、打牌、看有没有报错。

```bash
npm i -D playwright && npx playwright install chromium   # 第一次装
bash tools/tests/run_tests.sh                 # 跑全部（大约 15–25 分钟）
ONLY="t22 cardchk" bash tools/tests/run_tests.sh   # 只跑几个
PERF=1 bash tools/tests/run_tests.sh          # 连性能测试一起跑
bash tools/tests/run_tests.sh /path/to/dist   # 测别的构建
```

测试会把游戏复制一份「快速版」（所有等待时间缩成 1/10），截图和日志放在 `/tmp/nwt-test/`。每个测试文件第一行写着它测什么：

| 测试 | 测什么 |
|---|---|
| `t22` | 完整流程：第一层打到第四层通关 |
| `fight2` | 吸血鬼奶蛙打小怪、精英、首领 |
| `cardchk` | 所有卡牌的说明都算一遍；新卡逐张打出去 |
| `bossim` | 11 个首领 / 精英各打 7 回合 |
| `ss55t` | 两条 SS 线从头到尾 |
| `sec` | 秘密房间每个选项、新事件、寂静之海必出 |
| `t51` | 镜之间、后门 |
| `truend` | 真结局流程 |
| `junc5` | 岔路层 |
| `tavlock` | 酒馆连点不会多弹窗口 |
| `coll` | SS 隐藏路线不会盖掉隐藏房间 |
| `feat56` | 5.6 的塔况、遗物、天气牌、小院 |
| `lb` / `lbc` | 排行榜补传 |
| `fitt` | 几种屏幕比例下的适配 |
| `mh4` / `tit` / `bigperf` | 性能（CPU 降速 4 倍时的帧率） |

> 性能数字只能用来**比较**（改之前 vs 改之后），不能当成手机上的真实帧率。无头 Chrome 用 CPU 画图，手机用显卡，差别很大。

## 三、几个最重要的全局变量

整个游戏没有用框架，所有状态都是几个全局变量。记住这五个就能看懂一大半代码：

| 变量 | 是什么 | 存在哪 |
|---|---|---|
| `M` | **局外存档**（Meta）：解锁、成就、碎片、小院成长、最好成绩、通关次数……跨局保留 | `localStorage["nwt-meta"]`，`saveMeta()` 保存 |
| `S` | **这一局**的状态：英雄、血量、金币、牌组、遗物、地图、当前位置、各种剧情标记 `S.flags` | `localStorage["nwt-run"]`，`saveRun()` 保存。不在局里时是 `null` |
| `B` | **当前这场战斗**：敌人、手牌、抽牌堆、奶蛙池、回合数…… | 不存档。战斗外是 `null` |
| `A` | 声音（`A.ctx` 是 AudioContext，`A.music` / `A.sfx` 开关） | — |
| `PREV` | 「预览模式」开关。为了让手牌上显示「这张牌现在打出去是几点伤害」，游戏会**假装打一遍**，这时 `PREV` 是真的 | — |

`S` 里常用的字段：

```js
S.hero      // "naiwa" | "kungfu" | "knight" | "mage" | "vamp"
S.hp S.max S.gold
S.deck      // 牌组：[{id:"strike",u:0,k:"唯一编号",g:金卡,sh:闪卡词条}, ...]
S.relics    // ["cup","ring",...]
S.pots      // 药水 ["pheal",...]，S.potSlots 是格数
S.act       // 第几层，0 开始（0 泥沼回廊 … 4 星空之顶）
S.map S.row S.col S.path   // 地图和当前位置
S.cur       // 当前所在房间的信息，读档时用它恢复
S.flags     // 各种剧情标记：protoDone、arenaDone、cupFriend、curserDone、ayNote……
S.mod       // 今日塔况（"rain"、"party"…）
S.diff      // "easy" | "normal" | "hard"
S.junc S.dream S.fin   // 在岔路层 / 阿岳的梦 / 最终之地
```

`B` 里常用的字段：

```js
B.kind      // 战斗种类，见第六节
B.enemies   // [{id,n,hp,max,block,str,intent,turn,...}]
B.p         // 玩家这场战斗的状态：block 护盾、energy 奶力、str 力气、各种负面状态、pw2 能力牌效果
B.hand B.dp B.disc B.exh   // 手牌 / 抽牌堆 / 弃牌堆 / 消耗堆
B.pool      // 奶蛙池
B.eggs      // 场上的蛋
B.turn B.myTurn B.over
B.wx B.moon // 这场战斗的天气、月相
```

还有几个到处用的小工具（在 `game.js` 开头）：

```js
$("#id")  $$(".cls")        // 选元素
sleep(ms)                   // 等一下（会按游戏速度缩放）
rnd() ri(n) pick(arr)       // 随机数。用的是存档里的种子，读档后结果一样
toast("文字")               // 右下角提示
talk([[头像,名字,台词],...]) // 剧情对话，返回 Promise，点完才继续
ov(html) closeOv()          // 打开 / 关闭全屏弹窗
show("battle")              // 切换界面
has("relicId")              // 有没有某件遗物
ach("id")                   // 解锁成就
mk("cardId")                // 造一张牌
```

## 四、一局游戏从头到尾怎么跑

```
titleScreen()                  主页
  └ 点「开始冒险」→ 选英雄 → newRun()       建立 S：牌组、遗物、塔况、第一层地图
      └ openMap()               显示地图
          └ 点一个房间 → enterNode(类型)
                ├ "m"/"E"/"B"/"K"… → startCombat(kind) → 战斗 → win() / lose()
                ├ "q" → eventScreen()   随机事件
                ├ "r" → restSite()      休息
                ├ "s" → shopScreen()    商店
                ├ "v" → tavernScreen()  酒馆
                ├ "t" → treasure()      宝箱
                └ … 其他特殊房间（见第五节）
          win() → rewardScreen() → 选奖励 → openMap()
          打完这一层的首领 → actClear() → 下一层（可能先进岔路层 juncEnter）
      └ 打完第五层的大魔王：
          一周目：假结局
          二周目起（S.flags.truth）：可以宽恕 → 魔椅 chairStart → 阿岳的梦 S.dream → 最终之地 S.fin → 深渊龙蛙 → 真结局
  lose() → gameOver()：结算、给记忆碎片 earnShards()、回主页
```

**读档**：打开游戏时，如果 `localStorage` 里有 `nwt-run`，主页会出现「继续」。继续时用 `S.cur` 里记的房间类型重新调用 `enterNode(类型, true, S.cur)`。所以**进房间的代码要能处理「读档进来」的情况**（比如死斗场五连战打到一半退出，再进来要回到当前那一场）。战斗读档时会把血量、金币恢复到进这场战斗之前（`S.cur.snap`）。

## 五、地图和房间

- `genMap()` 生成一层地图：`MAPR`（13）行 × `COLS`（7）列的格子，每格是 `{r,c,t,nx,...}` 或 `null`。`t` 是房间类型，`nx` 是能走到的下一行的列号。
- 地图上从左往右走。**「下半层」**是指后半段（`GROW()` 之后的行），隐藏路线都放在这里。
- `hiddenPlace()` 在生成地图时，把一个普通房间随机换成隐藏房间（A / Y / Z），每种一局最多一次。
- 5.6 起 `genMap` 外面还包了一层：有 40% 几率再放一个秘密房间（W）。
- SS 隐藏路线（初号机、死斗场、诅咒师）是**后来插进去的**：`injectRoute(类型列表, …)` 在下半层找一条连着的路，把上面的格子换掉。5.6 起它会优先找只经过普通小怪 / 事件 / 精英 / 宝箱的路，不会盖掉隐藏房间、酒馆、商店、休息点。

房间类型 `t`：

| t | 房间 | 进去调用 |
|---|---|---|
| `m` | 小怪 | `startCombat("m")` |
| `E` | 精英 | `startCombat("E")` |
| `q` | 事件 | `eventScreen()`（10% 打怪、10% 流动商人） |
| `r` | 休息 | `restSite()` |
| `s` | 商店 | `shopScreen()` |
| `v` | 酒馆 | `tavernScreen()` |
| `t` | 宝箱 | `treasure()` |
| `K` | 守关首领 | `guardIntro()` |
| `B` | 本层首领（地图最右边那个大圈） | `bossIntro()` |
| `F` | 大魔王 | `startCombat("F")` |
| `C` | 最终之地的魔化首领 | `startCombat("C")` |
| `A` | 隐藏房间（连战四场） | `arenaStart()` |
| `Y` | 镜之间 | `mirrorStart()` |
| `Z` | 奶茶厂后门 | `zStart()` |
| `O` | 寂静之海的海底守墓者 | `seaBossIntro()` |
| `X` / `H` | 初号机线：冰原残骸事件 / 初号机 | `eventScreen("ss_ruins")` / `protoIntro()` |
| `P` / `D` | 死斗场线：斗场大门 / 五连战 | `eventScreen("ss_dsqgate")` / `dsqStart()` |
| `U` / `J` | 诅咒师线：书房 / 灭却诅咒师 | `eventScreen("ss_study")` / `csIntro()` |
| `W` | 秘密房间（5.6） | `secretRoom()` |

房间在地图上的图标和名字在 `NODE` 里（`{n:"名字", ic:"图片名"}` 或 `{e:"图标名"}`）。

**岔路层（x.5 层）**：`actClear()` 打完一层后有 25% 几率给一个「走进 x.5 层」的按钮（打完第三层的寂静之海一定出现）。岔路层用 `juncMap()` 生成，`S.junc=1`，走完回到正常的下一层。

## 六、战斗

### 开场：`startCombat(kind)`

`kind` 决定敌人从哪来、放什么音乐、用什么背景：

| kind | 是什么 |
|---|---|
| `m` / `E` | 小怪 / 精英。敌人组合从 `ENCS[S.act].easy / normal / elite` 里抽；如果房间格子带了 `grp`（`S.pendGrp`），就用指定的敌人 |
| `B` / `K` | 本层首领 / 守关首领（守关首领血量 ×0.7） |
| `F` | 大魔王 |
| `C` | 最终之地的魔化首领 |
| `W` | 魔椅的意志 |
| `H` | 初号机 |
| `G` | 金色奶蛙（打小怪时有小几率变成这个） |
| `R` | 回忆关（新手教程） |
| `Y` / `Z` | 镜之间 / 后门 |
| `O` | 海底守墓者 |
| `D` | 死斗场（5.5） |
| `J` | 灭却诅咒师（5.5） |

`startCombat` 建立 `B`、按遗物和塔况调整开局、设置每个敌人的第一个意图、画出战斗界面。开场对话放在 `B.introTalk`，开场效果放在 `B.introFx`，会在 2.6 秒后（BOSS 名字条放完）执行。

### 回合

```
startTurn()     回合开始：回合数 +1、护盾清掉（有例外）、处理中毒/诅咒等、抽牌、回奶力、天气效果、孵蛋
  玩家出牌：playCard(牌, 目标)
     → 扣奶力 → 执行 CARDS[id].fx(B, 升级等级, 目标)
     → B.hit(目标, 伤害, 次数) → dealEnemy() 算伤害 → 特效 hitFx() → 敌人死了 killEnemy()
     → 奶蛙池：打出某个家族的牌会往池里放对应的奶蛙，相邻三只一样的就消除（三连），触发家族爆发
endTurn()       回合结束：遗物结算（沙漏、七星拳谱…）、敌人一个个行动 enemyAct()、敌人选下一个意图
```

- **敌人意图** `e.intent` 是一个小对象：
  - `{k:"atk",v:12,x:3}`：攻击 12 点，打 3 下。可以带 `s:"weak",d:1`（顺便上虚弱 1）、`ult:"大招名"`（大招，会有横幅）、`pierce`（破防）、`pool:{t:"freeze",n:2}`（对奶蛙池做手脚）。
  - `{k:"def",v:15}`：叠盾。
  - `{k:"buff",s:"str",v:3}`：给自己加状态。
  - `{k:"debuff",s:"vuln",v:2}`：给你上状态。5.5 起可以再带 `s2`、`v2`，一次上两种。
  - `{k:"atkdef",v:10,b:12}`：攻击加叠盾。
  - `{k:"call",id:"敌人id"}`：叫一个小弟。
  - `{k:"add",card:"mud",n:2}`：往你的弃牌堆塞牌。
  - `{k:"charge"}`：蓄力。
  - `{k:"stun"}`：晕了。
  - `{k:"wait"}`：等着。
  
  `ENEMY[id].ai(e, 回合数)` 每回合返回下一个意图。敌人头顶的意图图标由 `intentHTML(e)` 画。
- **首领机制** 在 `BM[敌人id]` 里（`game.js` 搜 `const BM=`）：
  - `say`：开场喊的一句话。
  - `tip`：机制说明，第一次见到时弹出来。
  - `chip(e)`：显示在敌人身上的小标签，比如「蜡烛 3」。
  - `hit(e, 掉血)`：每次被打时调用。
  - `act(e)`：敌人回合、行动完之后调用。
- **首领挨打的特殊规则**集中在 `bossGuard(t, d)`：骸骨主教的骨甲、冰封奶蛙王的蜡烛、仆从护着诅咒师时伤害减半……都在这里改伤害。
- **伤害怎么算**：
  - 攻击牌的伤害 = 牌上的数字 + 力气 → 乘易伤、虚弱、天气月相加成 → 首领规则 `bossGuard` → 扣护盾 → 扣血。
  - 玩家挨打走 `dmgPlayer(伤害, 来源, raw)`。`raw` 表示「不吃护盾、不吃闪避」（比如中毒、自己扣血）。

### 胜负

- 敌人全死 → `win()`：
  1. 结算遗物：茶杯回血、金牙……
  2. 抓到的伙伴加进牌组，给经验 `gainXP`。
  3. 按 `B.kind` 分流：首领 → 剧情 → `actClear()`；死斗场 → `dsqWin()`；诅咒师 → `csWin()`；其他 → `rewardScreen()`。
- 玩家血量 ≤ 0 → `lose()` → `gameOver()`。

## 七、数据格式：卡牌 / 敌人 / 遗物 / 药水 / 状态

### 卡牌 `CARDS`（data.js，后来加的在 ss55.js）

```js
w_frostbite:{
  n:"冻疮",           // 名字
  cost:1,             // 费用；cu:0 表示升级后变 0 费
  type:"atk",         // atk 攻击 / skl 技能 / pow 能力（打出后整场有效）/ cur 诅咒 / sts 状态
  r:"C",              // 稀有度：C 普通 / R 稀有 / E 史诗 / S K T G P 特殊（不会出现在奖励里）
  fam:"chick",        // 家族：frog 奶蛙 / horse 奶马 / chick 奶鸡 / cat 奶猫 / egg 奶蛋 / none 无 / pal 伙伴……
  img:"egl",          // 卡面图片名
  tgt:1,              // 要选目标（单体攻击）
  exh:1,              // 用完消耗
  hero:"naiwa",       // 专属牌：只有这个英雄能拿到
  d:u=>`造成 ${U(u,7,10)} 伤害，冻伤 2`,   // 说明文字。u 是升级等级
  fx:(B,u,t)=>{ B.hit(t,U(u,7,10)); if(t.hp>0) B.apply(t,"frost",2) }   // 效果
}
```

- `U(u, 没升级的值, 升级后的值)`：按升级等级取数字。说明文字和效果要用同一个 `U(...)`，保证写的和做的一样。
- **奖励池**：`offerCards(张数, 种类)` 从 `POOL_HERO`（非专属牌）和英雄专属牌里抽。**新牌必须放进 `POOL_HERO` 才会出现在奖励里**（见第十四节）。
- 能力牌一般用 `PW(B, "名字", 数值)` 记一个效果，然后在 `startTurn` 之类的地方读 `B.p.pw2.名字`。

### 敌人 `ENEMY`（data.js）

```js
ss_champ:{
  n:"不灭的斗士", img:"e_v_champ",
  hp:[220,220],     // 基础血量范围。实际血量会按层数、周目、难度放大（mkEnemy 里算）
  h:320,            // 图片显示高度
  boss:1,           // 首领（elite:1 是精英）
  pd:"图鉴里的一句介绍",
  ai:(e,t)=>[{k:"atk",v:14},{k:"atk",v:8,x:2},...][t%4]
}
```

敌人台词在 `lines.js` 的 `ELINE[id] = {a:[攻击时], s:[特殊时], l:[残血时]}`。首领图鉴文字在 `BOSS_LORE[id]`。

### 遗物 `RELICS`

```js
r_horseshoe:{n:"马蹄铁", img:"hrl", r:"C", d:"奶马牌每一下伤害 +2"}
```

- `r` 是稀有度：
  - `C`：二级。
  - `R`：一级。
  - `E` / `Q` / `L` / `S`：特级，`S` 是剧情给的，不会随机出现。
- 遗物本身**只是一段描述**。效果要自己在相应的地方写 `if(has("r_horseshoe")) ...`。
- 遗物分级、卖价看 `rTierK()` 和 `relicSellP()`：特级 80、一级 50、二级 30。
- **随机遗物池** `RELIC_POOL` 是 data.js 读进来时算好的，后来在别的文件加的遗物要自己 push 进去（见第十四节）。

### 药水 `POTIONS`

```js
pantidote:{n:"解毒剂", c:"#5ac84a", d:"说明", fx:B=>{...}}   // tgt:1 表示要选目标
```

### 状态 `STAT`

`STAT[名字] = {n:"中文名", c:"颜色", d:"说明"}`。状态就是 `B.p` 或敌人身上的一个数字字段（`B.p.weak=2` 就是虚弱 2 层）。上状态统一走 `B.apply(对象, 名字, 层数)`，它会处理飘字、音效，以及「普通难度下中毒诅咒减半」这类规则。

## 九、两条 SS 线和 ss55.js 的「包一层」写法

`ss55.js` 在 `game.js` 之后加载。它几乎不改 `game.js` 的原文，而是把原来的函数**包一层**：

```js
{const _sc=startCombat;                 // 1. 把原来的函数存起来
 startCombat=function(kind){            // 2. 换成新的
   _sc.apply(this,arguments);           // 3. 先跑原来的
   if(kind==="D") setBg("teaarena");    // 4. 再做自己的事
 }}
```

这样能用，是因为 `game.js` 里的函数都是用 `function 名字(){}` 声明的全局函数，别的地方调用时会去找**当前**这个名字指向的函数。

注意：

- **同一个函数可能被包了好几层。** 比如 `startCombat` 在 `ss55.js` 里被包了 5 次左右（SS 线、遗物代价、塔况、小院、天文台……），每层各管一件事，后包的在外面。改的时候在 `ss55.js` 里搜 `=startCombat;` 能找到所有层。
- **`API`（就是 `B` 上的方法）也能这样包**：`API.apply`、`API.setWx`、`API.block`、`API.layEgg`。因为 `startCombat` 用 `Object.assign(B, API)` 把方法复制到 `B` 上，包 `API` 必须在战斗开始前完成（文件加载时就包好）。
- **`const` 声明的东西不能整个替换，但可以改里面**：`ENEMY`、`CARDS`、`RELICS`、`STORY`、`MODS`、`ACH` 都是 `const`，所以用 `Object.assign(CARDS, {...})`、`ACH.push(...)`。
- **有几处必须改 `game.js` 原文的**（包不进去的），都很短：
  - `startCombat` 里加了 `D` / `J` 两种敌人列表。
  - `win()` 里加了 `D` / `J` 的分流。
  - `enemyAct` 里的出手动画钩子 `enemyStrike` / `enemyCast`。
  - `dmgPlayer` 里的命中特效钩子 `playerImpact`。
  - 酒馆模板里留的 `ssCardX()` / `tavDiceHTML()` 位置。
  - `eventScreen` 里支持 `req`。

### 死斗场（第四层 SS）

- 酒馆接悬赏 → `S.flags.ssArena=1`。
- 地图打开时 `injectSS()` 在下半层插入 `P`（斗场大门）→ `D`（五连战）。
- `dsqStart()` / `dsqStep()` / `dsqWin()` / `dsqDone()`：五连战的进度存在 `S.dsq={st:第几步, g:押着的金币}`。`DSQ` 数组定义每一步打谁、对话是哪段。
- 不灭的斗士的机制在 `BM.ss_champ`：每回合「灌奶」力气 +2；一回合打够伤害就「打断管子」，让它晕一回合。
- 打完 → `S.flags.arenaDone`、`S.flags.cupFriend`（迷你奶茶杯跟着你，决战时会出来帮忙）。

### 灭却诅咒师（第五层 SS）

- 要求 `cupFriend`。到第五层时，`injectSS()` 插入 `U`（书房）→ `m`（仆从战）→ `J`（诅咒师）。
- 书房里带走阿岳的本子 → `S.flags.ayNote`（真结局多一段对话）。
- 诅咒师：
  - 「咒爆」的伤害 = 基础值 + 你身上负面状态的层数 × 2，敌人出手前才算。
  - 仆从活着时它只受一半伤害。
  - `B.fullCurse` 让中毒、诅咒这些不再减半。
- 打完 → `S.flags.curserDone`。
  - 梦境开头和年轻阿岳战前，会多出几段对话。实现方式：`STORY.dreamIn` 等改成了 getter，按标记动态拼接。
  - 最终之地多一个 `J` 格（`finMap` 被包了一层），是二番战 `curser2`。

## 十、存档、云存档、排行榜（toy.js）

### 存档

- `saveRun()` 写 `localStorage["nwt-run"]`，`saveMeta()` 写 `localStorage["nwt-meta"]`。
- 每次存档还会：
  - 把这一局复制一份到内存 `window.__nwbRun`（5.6，防止 localStorage 写不进去）。
  - 几秒后备份到 IndexedDB（`NWB`），localStorage 被清了也能从这里找回。
  - 通知云存档有新内容（`CLOUD.hot()` / `CLOUD.mark()`）。

### 云存档（`CLOUD`）

- B站 Toy 的 `toy.getCloudStorage` / `toy.setCloudStorage`，只有登录了 B站 才有。
- 整个 `{M, S}` 转成 JSON，切成每段 1000 字，存成 `tw_0`、`tw_1`……再用 `tw_m` 记一共几段。
- 打开游戏时比较「进度量」`nwProg()`：云端进度多就用云端的，本机多就保留本机的。两边合并时，熟练度、成就、最好成绩这类只增不减的东西取两边较大的（`nwMergeMeta`）。

### 排行榜（`LB`）

- 3 个榜：
  1. 爬塔积分。
  2. 最痛一击（单次最高伤害）。
  3. 真结局。
- `LB.submit(榜, 分数)`：
  - 先记到本机的 `M.lbBest`，再上传。
  - 上传失败会重试（5 秒、20 秒、1 分钟），结果记在 `M.lbLog`，排行榜页面下方会显示。
  - 分数太大被平台拒收时，自动改按 99,999,999 上传。
- `LB.resend()`：打开排行榜时，把本机记着、还没传上去的最好成绩补传一次。
- 平台只存一个数字，**不能存是哪个英雄打的**。

## 十一、画面：图片、背景、CSS、省电模式、屏幕适配

- **图片名**：`IMG("名字")` 返回图片地址。
  - 名字就是 `sr/out/名字.png` 去掉后缀，或者 `assets/_all.json` 里的名字。
  - `e_` 开头是敌人版。
  - 新图放进 `sr/out/`，代码里用到它的名字，构建时自动打包。
- **背景**：`setBg(种类)`。种类在 `BGIMG` 里映射到 `bg/*.jpg`，比如 `BGIMG.teaarena="teaarena"` → `bg/teaarena.jpg`。战斗用哪张由 `battleBg(kind)` 决定。
- **CSS**：
  - 所有样式在 `style.css`，后写的覆盖先写的。新加的样式写在 `/* ==LITE-AUTO== */` 这一行**之前**。
  - 这一行之后的内容由 `mklite.py` 自动生成：把会让画面一直重画的动画、阴影滤镜在省电模式下关掉。
- **省电模式**：
  - `<html class="lite">` 时生效。
  - 5.6 起会自动打开：连续两个 4 秒帧率低于 38 就切换（`ss55.js` 搜「自动省电」）。设置里可以手动开关，记在 `M.lite`。
- **屏幕适配**（5.6）：
  - 整个游戏画在 1280×720 的 `#stage` 上，`fit()` 按屏幕缩放、居中。
  - 用的是 `visualViewport`（真正看得见的区域），并避开刘海和圆角（`env(safe-area-inset-*)`）。
  - 两边多出来的地方，用当前背景图模糊铺满（`body::before`，图片地址由 `setBg` 写进 CSS 变量 `--fillImg`）。
  - 竖屏时整个画面转 90 度。
- **性能原则**：
  - 动画只动 `transform` 和 `opacity`，这两种显卡能直接处理。
  - 不要动 `left` / `top` / `margin` / `width` / `filter` / `box-shadow` / `background-position`，会导致每一帧都重新排版或重画。
  - SVG 里的元素做动画，整张 SVG 每帧都要重画（主页卡顿就是这个原因）。

## 十二、声音：配乐和音效

- **配乐**：
  - `music.js` 里的 `TR` 是所有曲子：`{bpm, lead:"主旋律乐器", bass, dr:"鼓", ch:[和弦], mel:[旋律]}`。
  - `mel` 一格是八分音符，数字是 MIDI 音高，`0` 是休止，`-1` 是延长。
  - `TVOL` 是每首曲子的音量。
  - `playMusic(名字)` 切歌，会按场景自动替换（比如在岔路层里，`battle` 会换成 `junc`）。
  - 乐器名必须是 `INST` 里有的。写错了会一直报 `INST[T.lead] is not a function`。
- **音效**：
  - `sfx("名字")`：合成音效，在 `sfx.js` 的大 switch 里。
  - `sxPlay("采样名", 音量, 音高, 延迟, {pan:左右})`：放采样。可用的采样名：`punch punchH blade claw slash schwing whoosh thud body clank glass rock boomx sub firew icecrack knock place coins` 等，完整列表看 `sx.js`。
  - `duck(比例, 毫秒)`：让配乐暂时小声一点，给重击让位。
  - 5.5 起敌人出手的动作和声音在 `ss55.js` 的 `enemyStrike` / `enemyCast` / `playerImpact`：按招式分重击、多段、远程、上咒，按体型分轻重。

## 十三、手把手

### 加一张牌

1. 在 `ss55.js`（或 `data.js`）里 `Object.assign(CARDS, { 新id:{...} })`，格式见第七节。说明 `d` 和效果 `fx` 用同一个 `U(...)`。
2. 放进奖励池：`POOL_HERO.push("新id")`。专属牌写 `hero:"英雄id"`，不用进 `POOL_HERO`。
3. 卡面图用现有的图片名就行；要新图就放进 `sr/out/`。
4. 构建，跑 `cardchk`：它会把所有牌的说明算一遍，并把新牌逐张打出去。

### 加一件遗物

1. `Object.assign(RELICS, { r_xxx:{n:"名字", img:"图", r:"C", d:"说明"} })`。
2. **放进随机池**：`RELIC_POOL.push("r_xxx")`。
3. 写效果：找到合适的时机（开局、回合开始、出牌后、受伤时……），包一层或加判断 `if(has("r_xxx"))`。常用的时机：
   - 每场开局：包 `startCombat`。
   - 回合开始：包 `startTurn`（注意它是 `async`，要 `await` 原函数）。
   - 打出一张牌后：包 `playCard`，比较 `B.played` 有没有变大，判断是不是真的打出去了。
   - 改伤害：包 `dealEnemy`（每一下都会调用），用 `B.curFam` / `B.curType` 判断是什么牌。
   - 改护盾：包 `API.block`。
   - 拿到遗物时：包 `gainRelic`。
4. 有代价的，代价也写进 `d` 里。

### 加一个敌人

1. `Object.assign(ENEMY, { id:{n, img:"e_图名", hp:[min,max], h:高度, ai:(e,t)=>[...][t%N]} })`。
2. 台词：`Object.assign(ELINE, { id:{a:[...], s:[...], l:[...]} })`。
3. 放进某一层的组合：`ENCS[层].normal.push(["id","另一个id"])`，精英放 `ENCS[层].elite`。
4. 有特殊机制就加 `BM.id = {say, tip, chip, hit, act}`。
5. 首领要加 `BOSS_LORE.id`（图鉴）。注意「首领图鉴」成就要求打败 `BOSS_LORE` 里的**全部**首领。

### 加一个随机事件

`Object.assign(EVENTS, { id:{act:层, n, img, t, o:()=>[...]} })`，格式见第八节。不想被随机抽到就加 `ss:1`。

### 加一个成就

`ACH.push({id, n:"名字", d:"怎么解锁", ic:"图标", hid:1 /*隐藏*/, h:"给多周目玩家的提示"})`，然后在对的地方调用 `ach("id")`。图标可用：`sword boom star q heart skull swirl coin shield chest deck storm` 等。

### 加一个塔况

1. `Object.assign(MODS, { id:{n, d} })`。
2. `MOD_ST.id="一个字"`（地图上的小标签）。
3. `MOD_GB.id=["好处","代价"]`（塔况介绍卡）。
4. 效果在相应的地方判断 `S.mod==="id"`。5.6 的「某类牌更容易拿到」用的是包了一层的 `offerCards` 加 `modWants(id)`。

### 加一个小院成长

1. `META.push({id, n, d:l=>说明, max:最高级, cost:l=>价格})`。
2. 挂到某一条路上：`YTREE` 里某一行的 `ids.push("id")`。同一行里，前一格点亮了才能点下一格。
3. 效果里用 `mlv("id")` 读等级（玩家在小院里关掉了的话读到 0）。

## 十四、踩过的坑

- **后加的遗物不会随机出现**：`RELIC_POOL` 在 `data.js` 读进来那一刻就算好了。5.5 加的天气遗物一度因此从来没出现过。新遗物一定要 `RELIC_POOL.push`。
- **后加的牌不会出现在奖励里**：同理，要 `POOL_HERO.push`。
- **`chooseReward` 自己会把选中的牌加进牌组**：不要在它后面再 `addCard`，否则会加两张（以前好几个事件有这个 bug）。
- **预览模式 `PREV`**：手牌上的数字是「假装打一遍」算出来的。效果里有随机、有副作用（加金币、弹提示、放音效）的，要判断 `if(PREV) return` 或 `!PREV`，不然光是看手牌就会触发。
- **`sleep` 会被测试缩短**：测试的快速版把 `sleep` 缩成 1/10。如果某段逻辑依赖「至少等了多久」，在测试里可能表现不同。
- **异步按钮要防连点**：等待玩家选择的窗口（选牌、选遗物、猜拳），检查条件和真正扣钱之间隔了一个 `await`。卡顿时玩家可能连点出好几个窗口，金币扣成负数。用一个「正在处理」的标记挡住（参考 `window.TAV_BUSY`）。
- **蛋的 `nw` 标记**：回合开始那一刻下的蛋要带 `nw:1`，否则同一个回合里就会被孵化逻辑减掉一回合。
- **同一个关键字的 `@keyframes` 不能写两次**：后写的会覆盖前面的。以前 `shine` 写了两次，导致主页按钮的高光一直在用会重画的那个版本。
- **`mklite.py` 会重写标记之后的内容**：新 CSS 写在 `/* ==LITE-AUTO== */` 之前。
- **乐器名写错不会报在加载时**，是播放时一直报错，要在测试日志里看。
- **文件不能超过 1 MB**：`game.js` 已经 500 KB 了。再大下去，考虑像 `ss55.js` 一样拆新文件；拆的时候 `build.py` 里有三处文件列表要一起加（拼文字、复制、检查头像）。
- **改了要构建、要测**：改完源码跑 `python3 build.py`，再跑 `bash tools/tests/run_tests.sh`。
